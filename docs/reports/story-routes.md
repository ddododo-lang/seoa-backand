### 갈래 사건이 이어지는 방법

갈래 사건은 판정이 `pending_event` 로 시작합니다(첫 답장). 원고 장면이 여러 답장에 걸치므로, 판정이 `state.scene`(그 사건)과 `scene_judges_left`(2)를 같이 넣습니다. 앱은 판정 state 를 통째로 합쳐 다음 `/chat` 에 보내니, **판정 2번(≈6턴) 동안 장면 블록이 계속 들어가고** 그 뒤 닫힙니다. 앱 코드 변경은 없습니다.

## 점검

```
git fetch && git checkout feat/story-routes && git pull && python eval_chat.py --scenario all --pause 10
```

- 결과 `eval_scenarios.md`. ❌ 가 없으면 PR #5(seoa-tone) → 이 PR 순서로 병합.
- `⚠ 원고 대사 없음` 은 그 턴에 원고 대사가 안 나왔다는 표시(장면이 여러 턴에 걸쳐 다음 턴에 나올 수 있어 ❌ 로 치지 않음). 두 턴 모두 ⚠ 면 블록을 손봐야 합니다.
- 새 시나리오만: `--scenario route_date`(또는 route_walk, route_alley, pursue_tease, pursue_care, rewind, moment_hurt, moment_plain, xmas_late, bonus_short, bonus_long, bonus_repeat, min_msgs, day_marker, departed).
- 판정 흐름 시나리오(`bonus_*`·`min_msgs`·`day_marker`·`departed`)는 실제 판정 모델의 플래그·`time_advance` 에 따라 결과가 갈릴 수 있습니다(예: `bonus_long` 은 판정 플래그가 없으면 +1 이 맞음, 표시함).

## 제가 정한 것

- **갈래 사건은 판정 2번 동안 이어 감**(`SCENE_JUDGES = 2`). 다른 사건이나 단계 장면이 생기면 그 턴은 그쪽을 먼저 넣습니다.
- **갈래가 정해지면 2~5단계 무작위 사건에서 갈래 사건 다섯(DATE·WALK_HOME·STORM·ROOFTOP·ALLEY)을 모두 뺍니다.** 브리프는 3단계 「다른 갈래 사건」만 말했지만, 「같은 갈래 사건 한 번만」을 지키려면 자기 갈래 사건도 무작위로 다시 나오면 안 되어서입니다. 6단계는 예전처럼 다 나올 수 있습니다.
- **2단계 갈래 사건은 앱이 route 를 정한 다음 판정에서 시작**합니다. 앱은 호감이 40 에 닿은 판정 **뒤에** route 를 정하므로, 그 판정 요청에는 route 가 아직 없습니다(약 3턴 늦게 시작).
- **「그 골목」의 비밀1 은 사건을 시작하는 판정에서 바로 공개로 넣습니다**(`revealed_secrets`). 그래야 그 장면 답장의 상태 칸에 비밀1 이 보이고 4단계 지침과 맞습니다. 갈래가 있으면 `_advance(4)` 의 자동 공개는 건너뜁니다 → 한 번만. 갈래가 없으면 예전 그대로.
- **5단계 붙잡기 장소는 모델이 옮깁니다.** 「유저가 찾아 나섰다」는 서버가 글자로 가리기 어려워서, 블록에 장소를 적어 두고 eval 로 확인합니다(사건 시작 장소인 STORM·ROOFTOP·ALLEY 는 모델이 비우면 서버가 채움).
- **남은 날 지문은 서버가 action 앞에 그대로 붙입니다**(모델에 맡기면 말을 바꿈). 「마지막 밤」은 남은 하루에 판정 시간대가 「밤」이 들어간 값으로 바뀐 첫 판정에 한 번(`state.last_night_told`). 남은 날이 0 이 되면 지문 없이 바로 `ending: departed`.
- **순간 선물 간격은 대화 기록의 「[유저가 선물함: 이름] · 순간 선물」 줄로 셉니다.** 서버는 상태가 없어 「열었지만 안 준」 순간은 모릅니다 → 앱 쪽 부탁(아래).
- **대화량 글자 수는 공백을 뺀 글자 수**, 같은 말 반복은 같은 판정 묶음 안에서 셉니다. 메시지는 `last_user` 를 줄바꿈으로 나눕니다(앱이 3턴을 줄바꿈으로 이어 보냄). 그래서 **유저 메시지 하나에 줄바꿈이 있으면 여러 개로 셉니다.**
- **최소 메시지 수는 판정 때 묶음 수만큼 더합니다.** 판정이 3턴마다라 「15번째에 오름」은 15개를 넘긴 첫 판정에서 오릅니다.
- **`progress` 를 `/judge` 응답에 늘 넣습니다**(DEBUG 와 무관, 숫자만이라 공개해도 됨). `changes` 는 지금처럼 DEBUG 때만.
- **크리스마스 기색은 정확한 수(10·5·2) 대신 구간(10~6·5~3·2~1)** 입니다. 브리프 점검 「남은 8 · 단계 3 → 기색」을 맞추려면 10 을 건너뛰어도 나와야 해서입니다. 구간마다 그 줄이 최근 서아 말에 없을 때 한 번이라, 줄은 예시 그대로 쓰게 했습니다.

**앱이 바꿀 것**
1. **되감기 지점 남은 날 3.** 지점 state 의 `departure_days_left` 를 7 → 3 으로. 에필로그 「7일째 밤」 문구도 원고 3일 판에 맞게.
2. **`episode_turns_left` 보내기.** 크리스마스 중 `/chat` state 에 자정까지 남은 유저 메시지 수(정수). 없으면 기색이 나오지 않습니다.
3. **시연 패널에 `progress` 표시.** `/judge` 응답 `progress`: `talk_bonus`(이번 보너스), `stage_bonus`/`stage_bonus_max`(이 단계 누적/8), `stage_user_msgs`, `min_msgs`, `min_msgs_left`.
4. **서버가 쓰는 state 값이 늘었습니다:** `scene`, `scene_judges_left`, `last_night_told`, `stage_bonus`, `stage_user_msgs`. 지금처럼 판정 state 를 통째로 합쳐 돌려보내면 됩니다. **되감기 스냅숏에도 같이 저장**해 주세요(되감은 뒤 남은 메시지 수·보너스가 지점 값으로 돌아가도록). 시연 패널로 단계를 바꿀 때는 `stage_user_msgs` 를 그 단계 최소 수 이상으로 넣어야 다음 단계로 오릅니다.
5. **`pending_event` 에 새 값이 옵니다:** `WALK_HOME`, `ALLEY`, `STAGE_UP_2·3·4·6`(PR #5), `DAYS_LEFT_2`, `DAYS_LEFT_1`, `LAST_NIGHT`. 지금처럼 답장 뒤 비우면 됩니다. 해금 지도(`unlock.event`)에 `WALK_HOME`·`ALLEY` 몸짓을 붙이려면 그 이름으로.
6. **순간 선물:** 서버는 「준」 순간 선물만 기록으로 알 수 있습니다. **열었지만 3메시지 안에 안 줘서 닫힌 선물**도 10메시지 동안 다시 열리지 않게 하려면, 앱이 그 id 를 그동안 `gift_moments` 에서 빼 주세요.
7. **판정 묶음(`last_user`)의 줄바꿈 = 메시지 경계로 셉니다.** 유저 메시지 안의 줄바꿈은 보낼 때 공백으로 바꿔 주면 대화량·최소 메시지 수가 정확해집니다.
8. **유저 메시지 수는 본 이야기만** 셉니다(에피소드 판정은 `progress: null`).
