## 제가 정한 것

1. **asked 로 바꾸는 때**: 서버는 답장(/chat)에서 state 를 돌려주지 않아서, 「답장을 만든 뒤」를 2→3 상승을 정한 판정에서 바로 asked 로 바꾸는 것으로 했습니다. pending_event 는 예전처럼 `STAGE_UP_3` 이고, system 을 만들 때 유저 이름이 있고 asked 면 STAGE_UP_3_NAMED 를 넣습니다(앱이 받는 사건 이름은 그대로).
2. **asked → accepted 한 박자 기다림**: 물은 판정 바로 다음 판정은 「물은 답장」을 판정하는 차례라 유저가 아직 답하지 않았습니다. 그때는 asked 를 유지하고(거절이 오면 그건 받음), 그다음 판정부터 거절이 없으면 accepted. 물은 차례는 `used_events.NAME_ASK`(그때의 turn)로 셉니다.
3. **판정 입력의 asked 줄**: 판정기가 이름 얘기인 줄 알도록 asked 일 때만 「아직 안 부름 (서아가 이름으로 부르고 싶다고 물어본 참)」으로 넣었습니다. STATE_BLOCK 쪽은 지시문 문장 그대로.
4. **5·6단계에서의 첫 거절**: 단계는 그대로(5·6단계 흐름을 바꾸지 않기), 호감 -10 과 refused 만. 사과하면 forgiven(단계 그대로). 2단계로 내리는 것은 3·4단계일 때만.
5. **사건 겹침**: 5단계의 DEPARTURE·남은 날 지문·LAST_NIGHT 가 예약돼 있으면 이름 사건으로 덮지 않습니다(이름 상태는 바뀜).
6. **2단계로 내릴 때 갈래 장면**: 3단계 갈래 장면(STORM·ROOFTOP)이 열려 있으면 닫습니다. 2단계에 폭우 장면이 이어지지 않게.
7. **호감 상한**: 거절 감점은 내린 단계의 상한 안에서 (예: 3단계 55 → 2단계 45, 2단계 상한 50).
8. **이름이 없는 예전 앱의 「이름 부르기」**: name_state 가 늘 none 이라 그대로면 「아직 안 부름」이 되어 4단계 뒤 대화에서 알게 된 이름도 안 부르게 됩니다. 예전처럼 돌아가게 user_name 이 비면 1~3단계 「아직 안 부름」, 4단계부터 「진지한 순간에 이름」(대화에서 알게 된 이름만, 지어내지 않음)으로 했습니다. 1~2단계에서 안 부르는 것은 지시문대로 모두에게 적용됩니다.
9. **STAGE_UP_4**: 「…너 이름, 아직 안 물어봤네.」 블록은 유저 이름이 없고 none 일 때만 넣고, 그 밖에는 4단계 상징 장면 블록을 넣지 않습니다(원고에 다른 대사가 없어 지어내지 않음). pending_event 값은 예전처럼 `STAGE_UP_4`.
10. **STAGE_4 지침 줄**: 지시문 목록에는 없지만 「처음으로 그 이름을 부른다」가 이름 흐름과 부딪쳐서, 유저 이름이 있으면 「이름 부르기」를 따르게 고쳤습니다(유저 이름이 없으면 예전 문장 그대로).
11. **refuse_name·apologize 는 stage_flags 에 넣지 않음**: 판정 flags 로만 돌려줍니다(단계 조건과 무관).
12. **이름 흐름은 user_name 이 있을 때만 돎**: user_name 이 빈 채로 refuse_name·apologize 가 와도 아무것도 바뀌지 않습니다.
13. **user_name 이 있는데 이미 3단계 이상인 예전 저장**: none 그대로 두고 이름을 묻지 않습니다(「아직 안 부름」). 다음에 3단계로 다시 오를 일이 없으면 이름을 부르지 않습니다.

## 앱 팀에 전할 것 (Bii0411/Moti)

1. **user_name 보내기**: /chat 과 /judge 의 `state.user_name` 에 시작 화면 닉네임(1~8자)을 매번 넣어 주세요. 서버는 앞뒤 공백·줄바꿈·`{ } " 「 」` 를 빼고 8자로 자릅니다. 저장하지 않습니다.
2. **judge_soon**: /judge 가 돌려준 `state.judge_soon` 이 true 면, 다음 서아 답장마다(3턴 모으지 말고) 바로 /judge 를 불러 주세요. 이름을 물은 뒤·거절 뒤 사과를 기다리는 동안만 true 입니다.
3. **단계가 내려갈 수 있음**: 이름 거절로 `state.stage` 가 3·4 → 2 로 내려갈 수 있고, 사과로 2 → 3 으로 돌아갈 수 있습니다(이때 `stage_up` 은 false, 3단계 상징 장면 없음). 단계 표시·해금은 `state.stage` 를 그대로 따라 주세요.
4. **새 state 키는 그대로 돌려보내기**: `user_name`·`name_state`·`judge_soon` 과 `used_events.NAME_ASK` 를 받은 그대로 다음 요청에 보내 주세요.
5. **새 pending_event 값**: `NAME_REFUSED`·`NAME_FORGIVEN`·`NAME_REFUSED_AGAIN`. 다른 사건처럼 답장 뒤 비워 주세요.
6. **새 flags 값**: 판정 결과 `flags` 에 `refuse_name`·`apologize` 가 올 수 있습니다. 해금 조건에는 쓰지 않습니다.

## S2-1 이름 장면 반응을 같은 답장에서 바로 · 이름 장면 중 무작위 사건 막기

브랜치: `feat/s2-1-name-now`

실서버에서 「싫은데? 그냥 사장님이라고 불러」에 서아가 장난스럽게 받고, 다음 답장에서야 「…싫어? 그럼 말구.」가 나왔습니다(사과도 같음). 판정이 상태를 바꾼 뒤 다음 답장에 사건이 붙기 때문입니다. 용서 직후 BLACKOUT 이 끼어든 일도 있었습니다.

### 바뀐 파일

| 파일 | 바뀐 것 |
| --- | --- |
| `yoon_seoa_prompt.md` | 새 블록 NAME_WATCH (지시문 원고 세 줄, 앞에 `[asked]`·`[refused]`·`[forgiven]` 표시) |
| `engine.py` | `_name_watch`(/chat system 에 name_state 에 맞는 줄만), `_apply_name` 이 last_reply 에 원고 대사가 있으면 pending_event 를 넣지 않음, state 키 `name_quiet`, `_name_scene_quiet` 로 무작위 사건 쉬기 |
| `prompt_loader.py` | NAME_WATCH 를 필수 블록에 |
| `tests/test_s2_1_name_now.py` | 새 테스트 9개 |

### 흐름

| name_state | /chat 에 넣는 NAME_WATCH 줄 |
| --- | --- |
| asked · accepted | 거절하는 뜻이면 이번 답장을 「…싫어? 그럼 말구.」 장면으로 |
| refused | 사과면 「…이번 한 번만 넘어가 줄게. {이름}.」 장면으로, 아니면 서운한 채로 짧게(이름 안 부름) |
| forgiven | 다시 부르지 말라는 뜻이면 「…두 번은 안 물어봐, 사장님.」 장면으로 |
| none · closed · 이름 없음 · 크리스마스 | 넣지 않음 |

- 판정이 NAME_REFUSED·NAME_FORGIVEN·NAME_REFUSED_AGAIN 을 정할 때, 판정한 답장(last_reply)에 「그럼 말구」「넘어가 줄게」「두 번은 안 물어봐」가 이미 있으면(띄어쓰기 무시) pending_event 를 넣지 않습니다. 상태·단계·호감 변화는 그대로입니다. 없을 때만 지금처럼 다음 답장에 넣습니다.
- 무작위 사건(INJURY·BLACKOUT·STORM 등, 조연 포함)은 name_state 가 asked·refused 인 동안, 그리고 이름 사건을 정한 판정 뒤 유저 메시지 3개 동안 고르지 않습니다.

### 확인 결과

- `.venv\Scripts\python.exe -m unittest discover -s tests -v` → **Ran 136 tests, OK** (S2-1 새 테스트 9개).

### 제가 정한 것 (S2-1)

1. **NAME_WATCH 는 블록 하나**: 세 줄을 한 블록에 두고 줄 앞 `[asked]` 같은 표시로 골라 넣습니다(표시는 빼고 넣음).
2. **NAME_WATCH 를 넣지 않는 답장**: 이름 사건(EVENT_NAME_*)이 이번 답장에 이미 예약돼 있을 때, 그리고 이름을 묻는 답장(STAGE_UP_3 + asked) 자체에는 넣지 않습니다. 두 지시가 부딪치지 않게.
3. **쉬는 메시지 셈**: 새 state 키 `name_quiet`(0~3). 이름 사건을 정한 판정에서 3, 다음 판정부터 그 판정의 유저 메시지 수만큼 줄입니다. 원고 대사가 답장에 이미 나와 pending 을 넣지 않은 때도 3으로 둡니다.
4. **갈래 사건도 같이 쉼**: 지시문은 `_tick_events`(무작위)만이지만, 사과로 3단계에 돌아가자마자 갈래 사건(STORM·ROOFTOP)이 붙는 것도 같은 문제라 같은 동안 미룹니다. 갈래 사건은 한 번뿐이라 쉬기가 끝난 뒤 판정에서 나옵니다.
5. **쉬는 동안 셈은 계속**: 짧은 답·조용한 턴 수는 그대로 쌓여서, 쉬기가 끝나면 조건이 찬 사건이 바로 나올 수 있습니다.

### 앱 팀에 전할 것 (S2-1)

- 새 state 키 `name_quiet` 도 받은 그대로 돌려보내 주세요.
- 이름 거절·사과 장면이 같은 답장에서 바로 나오면 그 판정의 `pending_event` 는 비어 있습니다(단계·호감은 바뀜).

## S2-2 크리스마스는 처음부터 이름으로만
