### 한 답장에 들어가는 것의 우선순위

판정이 다음 답장의 사건(pending_event)을 정하는 순서와, /chat 이 블록을 고르는 순서입니다. 위가 먼저이고, 아래 것은 비어 있을 때만 정해집니다(덮어쓰지 않음).

1. **위기·엇갈림 사건** `CRISIS`·`RIFT_START`·`RECONCILE_OPEN` (이름 사건이 덮지 못함)
2. **단계 상징 장면** `STAGE_UP_n` (마음 확인 뒤면 그 앞에 WON_*). 이름을 묻는 장면 STAGE_UP_3_NAMED 도 여기
3. **이름 사건** `NAME_REFUSED`·`NAME_FORGIVEN`·`NAME_REFUSED_AGAIN` (위 1·갈래 장면·밤 마무리는 덮지 않음). 이름 장면 중·직후 3메시지는 아래 4~6을 미룸
4. **밤 넘기기**: 「[다음 밤]」 첫마디(그 답장은 다른 사건 없음) > `NIGHT_END` 마무리(열린 갈래 장면·이름 장면 중엔 미룸)
5. **갈래 핵심 사건** 시작(DATE·WALK_HOME·STORM·ROOFTOP·ALLEY) → 마칠 때까지 장면 블록 이어 감
6. 6단계 조연 마무리 → **무작위 사건·조연** (열린 갈래 장면·밤 넘기기·이름 장면 중엔 없음)
7. 속마음 힌트(사건이 없는 답장에만)

## 위기·엇갈림·화해 판정 변경

- **위기(on)**: CRISIS 를 정한 다음 판정은 「소식 답장을 판정하는 차례」. 메시지 하나면 0개로(소식 전), 여럿이면 첫째만 빼고 셈. 그 판정의 판정 입력에 `[위기 판정] …`과 「첫 번째 유저 메시지는 서아가 소식을 꺼내기 전의 말이다…」를 넣음. 위기 중 모든 판정에 `[위기 판정]` 지시(진심·붙잡음·오해 풀기는 정확한 단어 없이도 sincere·pursue, 장난·짧은 맞장구는 아님). 제한 6개·HINT_5(3개째) 그대로. 위기 전 메시지의 플래그는 쓰지 않음(그 판정 flags 는 5단계 판정에 안 들어감).
- **성공 대사**: 판정한 답장에 「…연기 아니지. 이번엔.」(연기아니지) · 「…내려가자. 같이.」(내려가자+같이) · 「…늦었잖아. 그래도, 왔으니까.」(늦었잖아+왔으니까)가 공백 무시로 있으면 flags 가 비어도 성공. 이미 나왔으면 `won_line` 없음(다음 답장에 다시 안 넣음), 안 나왔으면 다음 답장 STAGE_UP_6 앞에 WON_*(S4 그대로).
- **엇갈림(rift)**: RIFT_START 답장 뒤 메시지(위와 같은 방식으로 첫 판정은 첫째 빼고)의 apologize·sincere → `rift_sorry = true`. `withdraw` → false. 이름 사과는 빼고 봄. 화해의 문은 그대로 「며칠 뒤 밤」부터 메시지 6개 뒤(기억이 있어도 반드시 겪음). 문 답장을 판정하는 차례 다음부터(문 뒤 유저 답) apologize·sincere 또는 `rift_sorry` 이고 그 답에 withdraw 가 없으면 화해. `rift_sorry` 가 있으면 문 뒤 /chat 에 RECONCILE_REMEMBERED 지시(같은 말 다시 요구 안 함)를 붙이고 HINT_6(「미안하다는 말 하나면…」)은 안 냄.
- **예비 지문**: CRISIS·RECONCILE_OPEN 답장 하나만 판정한 때(judge_soon 이라 보통 그럼) 그 답장이 「…」면 같은 사건을 다시 예약. RIFT_START 는 그 밤의 마무리라 다시 넣지 않음(RIFT 블록이 엇갈림 내내 들어감).
- 실패 → 엇갈림, `rewind_offer`, 호감 40 은 그대로.

## 단계 기억 변경

- 단계 기록 요청은 `stage_note_queue` 목록. **정상으로 오른 단계**(`_advance`: 1→2 … 5→6)만 넣음. 이름 흐름의 내림·사과로 다시 오름은 넣지 않음. 이미 `stage_notes` 에 있는 단계·이미 목록에 있는 단계는 안 넣음.

- 판정 입력: `[단계 기록 요청] N단계(이름)를 아래 [단계 기록용 대화]만 보고 한 문장으로. 그 단계가 끝난 뒤에 일어난 일은 넣지 않는다.` + 대화. need_summary 와 상관없음(요약 요청과 따로). 기억용 AI 호출은 늘리지 않음(「[다음 밤]」만 온 판정은 여전히 모델을 안 부르므로 그때는 기록도 안 함).
- 유지: 기록 80개, 요약(need_summary 때), 약속 5개, 본편·크리스마스 분리(크리스마스는 요청·저장 안 하고 목록을 보관만).

## 제가 정한 것

1. **「마침」을 답장 수로**: 지시의 기준(시작 답장 + 유저 메시지 3개)을 그대로 `scene_msgs ≥ 4` 로. 앱은 3개씩 묶어 판정하므로 판정한 마지막 답장만 보임 → 묶음 수만큼 세고, 마지막 답장이 「…」면 하나 뺌(묶음 중간의 「…」는 서버가 알 수 없음). 시작 답장이 「…」였으면 장면 블록이 다음 답장에도 들어가므로 따로 다시 예약하지 않고, 첫 정상 답장이 시작 답장 노릇을 함(장소도 그 답장이 옮김). 특정 대사 일치에 기대지 않음.
2. **예비 지문 판단**: 판정한 답장(last_reply)이 「…」 또는 「...」 그대로면 예비 지문으로 봄(서버 FALLBACK 의 모양).
3. **무한 반복·영구 정지**: 갈래 장면은 다시 예약하지 않고 정상 답장을 기다리므로 반복이 없음. CRISIS·RECONCILE_OPEN 은 「…」일 때만 다시 넣고 매번 유저 메시지가 있어야 하므로 루프가 아님. 횟수 상한은 두지 않음(모델이 계속 실패하면 대화 자체가 안 되는 상황이라).
4. **밖에 나가자는 말(outside) = 2일째 밤 2단계 핵심 사건의 시작 신호**: 호감 15 전이라도. 첫 밤(NIGHT_END_2 전)이면 밤 순서를 지키려 기다림. 3·4단계에는 적용 안 함. 「이미 밖」은 지금 장소가 바 1·2층이 아닌 것으로 봄(stage_flags 의 outside 는 앞 밤 것일 수 있어서).
5. **갈래 기본값**: 서버는 장난·다정 횟수를 모르므로 이 단계 stage_flags 로: tease 만 있으면 tease, 그 밖(둘 다·없음)은 care(동점 = 다정 규칙). 갈래 사건 차례(2단계: NIGHT_END_2 를 지난 다음 밤, 호감 15 또는 outside)에만 정함. 3·4단계에서 route 가 없는 예전 저장도 같은 규칙.
6. **3→4·4→5 도 route 필수**: 갈래가 없으면 그 단계 갈래 사건 차례에 정해지므로 영구 정지가 없고, 「실제로 겪은 뒤에 다음 단계」 원칙을 갈래 없는 저장에도 맞춤. 이 때문에 S4 의 「갈래 없으면 sincere 만·호감 55 만」 규칙은 없어짐.
7. **중단된 장면은 처음부터 다시**: 밤 넘기기·이름 흐름으로 닫힌 장면은 `ROUTE_x` 를 지워 다시 예약됨(블록의 「진행 중이면 다음 대목으로」 문장이 대화 기록을 보고 이어 감).

9. **성공 대사로 성공 판단**: 장난 「연기아니지」, 다정 「내려가자」+「같이」, 화해 「늦었잖아」+「왔으니까」(공백 무시). 「내려가자」만으로는 옥상 장면의 일상 말과 헷갈릴 수 있어 두 조각을 요구.
10. **엇갈림 기억 범위**: RIFT_START 답장 뒤(그 밤의 한 번 답 포함)부터 문이 열리기 전·후 모두. 「[다음 밤]」 줄은 메시지가 아님. 문을 연 답장을 판정하는 차례에는 화해하지 않고(유저가 문을 보기 전), 그다음 유저 답에서 반영. 화해하면 `rift_sorry` 는 false.

## 프런트 연동 ([78] 지시문에 그대로 옮길 수 있게)

### 1. 갈래(route) 정하는 시점과 조건

- 키: `state.route`, 값 `"tease"` 또는 `"care"`.
- **정하는 때**: /judge 응답에서 아래가 모두 맞으면, **다음 요청(/chat·/judge)을 보내기 전에** 앱의 장난·다정 집계로 정해 state 에 넣는다.
  - `state.stage == 2`
  - `state.route == null`
  - `state.night_next == "NIGHT_START_2"` 이거나 `state.used_events` 에 `"NIGHT_END_2"` 키가 있음 (= 2단계 첫 밤 마무리가 정해짐. 늦어도 「[다음 밤]」 /chat 전)
  - 기존 조건(호감 40 이상 또는 outside)이 이보다 먼저 오면 그때 정해도 된다.
- **값**: 장난 집계 > 다정 집계면 `"tease"`, 그 밖(동점 포함)은 `"care"`.
- **바꾸지 않기**: `state.route` 가 이미 값이면(서버가 정했든 앱이 정했든) 절대 바꾸지 않는다. 서버는 2일째 밤 갈래 사건 차례에 route 가 null 이면 스스로 정해 `state.route` 로 돌려준다(그 판정의 `pending_event` 가 `DATE` 또는 `WALK_HOME`). 앱은 그 값을 그대로 저장·표시한다.
- 예: 받은 state `{"stage": 2, "route": null, "night_next": "NIGHT_START_2", …}` → 앱 집계 장난 3·다정 3 → 다음 요청 state 에 `"route": "care"`.

### 2. 새·바뀐 state 키 처리

- 새 키 `scene_msgs`(정수)·`rift_sorry`(bool)·`stage_note_queue`(배열)를 **받은 그대로 다음 요청에 보낸다.** 앱이 값을 만들거나 고치지 않는다.
- `stage_note_due` 는 서버가 `stage_note_queue` 로 계산한다(앱은 읽기만, 보내도 됨).
- `route` 는 위 1번. `scene`·`scene_judges_left`·`used_events` 도 그대로 돌려보내기(S4 와 같음).
- 판정 응답 `flags` 에 `"withdraw"` 가 올 수 있다. 몸짓 해금 조건에는 쓰지 않는다(무시).

### 3. 요청·응답·판정 조건 변경

- 요청·응답 필드 모양은 그대로. 새 pending_event 값 없음.
- `pending_event` 는 **/chat 이 성공(HTTP 200)해 답장을 보여 준 뒤에만** 비운다. /chat 이 실패(502)해 답장을 못 보여 줬으면 비우지 말고 다음 /chat 에 그대로 보낸다(서버는 비워지지 않은 사건을 「아직 안 나감」으로 본다).
- /judge 의 `last_reply` 에는 마지막 서아 답장 글을 그대로 넣는다. 「…」(예비 지문)도 그대로 — 서버가 그 답장을 장면·사건 답장으로 세지 않는다.
- `last_user` 는 지금처럼 메시지마다 줄바꿈(메시지 안 줄바꿈은 공백으로).
- 같은 사건이 다시 올 수 있다: `CRISIS`·`RECONCILE_OPEN`(직전 답장이 「…」였을 때), 갈래 장면(밤 넘기기·이름 흐름으로 중단됐을 때). 다른 사건처럼 넣고 비우면 된다.
- `judge_soon` 규칙 그대로(true 면 다음 서아 답장마다 바로 /judge).

### 4. stage_note_due 때 recent 보내기

- 조건: 받은 `state.stage_note_due` 가 null 이 아니면(= `state.stage_note_queue` 가 비어 있지 않으면) **need_summary 와 상관없이** 다음 /judge 에 `recent` 를 보낸다.
- 키·개수: `recent: [{"r": "u"|"c", "t": "…"}]`, 최근 대화 **80개**(대화 기록 `history` 와 같은 범위, 최소 24개). 「[다음 밤]」 줄은 넣어도 서버가 뺀다.
- 서버는 그중 끝난 단계 구간만 잘라 쓰고, 모자라면 요청을 미룬다(다음 판정에서 다시). 기록이 되면 `stage_note_due` 가 다음 단계나 null 로 온다.
- 예: `{"char": "seoa", "state": {…, "stage_note_due": 2}, "last_user": "응\n그래", "last_reply": "…", "need_summary": false, "recent": [… 80개]}`

### 5. 사건 완료와 밤 넘기기에 필요한 앱 처리

- 갈래 장면은 서버가 「시작 답장 + 그 뒤 유저 메시지 3개 정상 답장」으로 마침을 정한다. 앱은 위 3번(성공한 답장 뒤에만 pending 비우기, last_reply 그대로)만 지키면 된다.
- 밤 넘기기는 S4 그대로(`night_next` → 마무리 답장 → 유저 한 번 답 → `night_card` 시간 카드 → 「[다음 밤]」 /chat → 바로 /judge). 「[다음 밤]」은 두 번 보내지 않는다(보내도 서버가 날짜를 다시 안 늘림).
- 밤 넘기기 중(`night_next` 가 있음)에는 단계가 오르지 않는다.

### 6. 초기화·되감기·에피소드 분리

- **새 게임**: 새 키를 빼고 보내면 서버 기본값(`scene_msgs` 0, `rift_sorry` false, `stage_note_queue` [])으로 시작한다.
- **되감기**(`rewind_offer` → [되감기]): 엇갈림이 되기 전 저장한 state 를 **통째로** 되돌린다(`rift_sorry`·`crisis`·`crisis_msgs`·`used_events`·`stage_note_queue` 포함). 섞어 되돌리지 않는다.
- **크리스마스(episode s2)**: 본편 state 키(`route`·`scene_msgs`·`rift_sorry`·`stage_note_queue` 등)는 앱이 그대로 보관만 하고, 에피소드가 끝나면 본편 state 로 돌아간다. 서버는 에피소드 중 이 값을 쓰거나 바꾸지 않는다. 에피소드에서 route 를 정하지 않는다.
