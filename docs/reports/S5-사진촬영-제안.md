# S5 서아의 사진 촬영 제안 — photo_3 · photo_6

브랜치: `feat/photo-ask` (커밋 [S5] 사진 촬영 제안 이벤트)
관계 3단계(갈래 장면 장소)와 6단계(연인 일상)에서 서아가 먼저 사진을 찍자고 한다. 기존 `/chat` 한 번 안에서 지시만 더하고, 확정 대사가 실제로 나온 답장에만 `photo_ask` 신호를 붙인다. 추가 모델 호출·`/judge` 호출 없음. 관계 상승 조건·호감·기억·밤 넘기기·위기·화해·크리스마스는 그대로.

## 실제 발동 조건

모두 `/chat` 요청의 state 만 보고 정한다. `/chat` 은 state 를 바꾸지 않는다.

**지원 신호**: `photo_ask_v` 가 정수 `1` 이고 `photo_asks` 가 배열일 때만. 그 밖(키 없음·`true`·`"1"`·`2`·배열 아님)이면 지시도 넣지 않고 응답에 `photo_ask` 키도 없음(예전 응답과 같음).

**공통 제외** (하나라도 맞으면 이번 답장엔 없음, 다음 정상 대화에서 다시 봄. 아무 state 도 바꾸지 않음):
- 에피소드(크리스마스) 중
- `pending_event` 가 있음(이름 장면·단계 상징 장면·조연·무작위 사건·밤 마무리·위기 사건 모두)
- `night_next` 가 있음(밤 마무리 중) 또는 메시지가 「[다음 밤]」
- 이번 답장에 속마음 힌트가 들어감
- 이름 장면 중·직후(`name_state` asked·refused, `name_quiet` > 0)
- 위기·엇갈림(`crisis` on·rift), 실패 엔딩(`departed`)
- 선물 메시지(「[유저가 선물함: …」), 포즈 부탁(몸짓 목록에 있는 「○○ 해 줄래?」)

**photo_3** (본편 `stage` 3, `photo_3` 이 `photo_asks` 에 없음, `route` 가 tease·care):
- 그 갈래 3단계 장면(장난 STORM / 다정 ROOFTOP)이 시작됨: `used_events` 에 `ROUTE_STORM`·`ROUTE_ROOFTOP`
- 그 장면이 아직 예약 상태가 아님: `pending_event` ≠ 그 장면 (시작 답장 자체에는 없음)
- 현재 장소가 그 장면 장소: STORM → 「바 '라스트 오더' 2층」, ROOFTOP → 「바 옥상」. 장면 시작 답장이 예비 지문이면 장소가 안 바뀌므로 여기서 걸러짐
- 장면이 아직 열려 있고 `scene_msgs` 가 0(판정 묶음 때문에 아직 셈 전)이면, 기록의 마지막 서아 답장이 예비 지문(「…」·「...」·서버 대체 응답)이 아닐 때만
- 장면이 끝났어도(`scene` null) 3단계이고 그 장소면 발동. 밤 넘기기로 장면이 중단되면(`ROUTE_*` 지움) 장면이 다시 시작될 때까지 기다림

**photo_6** (본편 `stage` 6, `photo_6` 이 `photo_asks` 에 없음):
- `ending` 이 `"stayed"` (서버가 첫 아침 → 그 갈래 조연 마무리가 나온 뒤 정함)
- 그 갈래 조연 차례(`mari_step`/`taeo_step`)가 3 — stayed 가 되면 항상 3
- photo_3 을 놓쳤어도 photo_6 은 따로 발동

**신호를 내는 조건** (지시를 넣은 답장에서):
- 모델 답장의 `dialogue` 에 확정 대사가 통째로 있음(공백·따옴표·문장부호는 빼고 비교, 「...」/「…」 차이 무시)
- 답장이 장소를 바꾸지 않음(`location` 이 null 이거나 지금 장소와 같음)
- 같은 답장에 순간 선물 신호(`gift_moment`)가 없음
- 맞으면 `photo_ask` 를 붙이고 `emotion` 을 원고 값(도발·설렘·기쁨)으로 고정. 아니면 `photo_ask: null` → 앱이 기록하지 않으므로 다음 정상 대화에서 다시 지시

## 요청·응답 예시

요청(`POST /chat`, 3단계 장난 갈래, STORM 장면 중):

```json
    "stage": 3, "route": "tease", "scene": "STORM", "scene_msgs": 1,
    "location": "바 '라스트 오더' 2층", "pending_event": null,

    "photo_ask_v": 1, "photo_asks": []

```

응답:

```json
{
  "action": "서아가 입꼬리를 올리며 당신을 빤히 바라본다.",
```

## 앱 팀에 전할 것

- 새 앱은 `/chat`·`/judge` 요청 state 에 `photo_ask_v: 1`, `photo_asks: [...]` 를 넣는다.
- `photo_ask` 가 null 이 아니면 제안을 보여 준 것으로 보고 그 `id` 를 `photo_asks` 에 더해 다음 요청부터 보낸다. 서버는 기록된 id 를 다시 제안하지 않는다. 촬영을 실제로 했는지는 서버가 보지 않는다(관계 단계와 무관).
- `/judge` 는 받은 `photo_ask_v`·`photo_asks` 를 그대로(정리만 해서) 돌려준다. 판정 중에 `/chat` 이 사진 제안을 내면, 판정 응답의 state 로 덮어쓸 때 `photo_asks` 를 잃을 수 있다 — **앱의 `photo_asks` 와 판정 응답의 것을 합쳐서(합집합) 보관**해 주세요.
- 촬영 전용 포즈 `p01` 은 `photo_ask.pose` 로만 오고 `motion_list`·`motion_id` 에는 쓰지 않는다. 답장의 `motion_id` 는 평소대로.
- `face`·`camera_face` 값(smirk·soft·joy / wink·shy·soft)은 지시문 규격 그대로. 앱 표정 이름과 다르면 알려 주세요.
- 예전 앱의 `/judge` 응답 state 에는 `photo_ask_v: 0`, `photo_asks: []` 두 키가 새로 보인다(그대로 돌려보내면 됨, 동작 영향 없음).

## 하위 호환성

- 지원 신호가 없으면 `/chat` 응답 키·system 지시가 예전과 같다(테스트 `test_old_app_unchanged`).
- 사진 제안은 state 를 바꾸지 않고, 다른 사건이 있으면 물러서므로 `pending_event`·장면 셈·밤 넘기기·위기·화해·단계 상승에 영향이 없다.
- 크리스마스 에피소드는 손대지 않음(에피소드 중엔 발동 없음).

## 제가 정한 것

1. **지원 신호 판정**: `photo_ask_v` 는 정수 1만 인정(`true`·`"1"` 은 아님). `photo_asks` 가 배열이 아니면 무엇을 보여 줬는지 알 수 없어 이번 요청은 미지원으로 처리. 배열 안의 모르는 값·중복은 버리고 진행.
2. **6단계 기준은 `ending == "stayed"`**: `morning_done` 은 따로 보지 않음. 6단계 메시지 15개로 stayed 가 되는 경로에서는 `morning_done` 이 false 로 남아 영영 발동하지 않을 수 있어서, 서버가 「일상」으로 넘긴 신호인 stayed 를 기준으로 함(stayed 가 되면 조연 차례도 3).
3. **속마음 힌트가 들어가는 답장·이름 장면 중·순간 선물 신호가 나온 답장**에도 넣지 않음(지시가 겹치지 않게). 다음 정상 대화에서 다시 봄.
4. **판정 지연 보완**: 장면이 열려 있고 `scene_msgs` 가 0이면, 기록의 마지막 서아 답장이 예비 지문인지로 「첫 정상 답장이 나갔나」를 판단. 장소가 그 장면 장소가 아니면 언제나 대기.
5. **대사 일치 비교**: 공백·따옴표·문장부호(. , ! ? ~ … ·)를 빼고 확정 대사 전체가 dialogue 안에 있으면 일치. 지문(action)은 원고처럼 「조금 바꿔도 된다」로 두고 검사하지 않음. 신호가 나가면 `emotion` 은 원고 값으로 고정.
6. **같은 장소를 다시 적은 답장**(`location` = 지금 장소)은 장소 이동으로 보지 않음.
7. **지시 블록의 안내 문장**(「먼저 이번 유저 메시지에 자연스럽게 답하고…」)은 모델 지시라 새로 씀. 서아의 지문·대사·emotion 은 지시문 원고 그대로.
8. **응답의 `photo_ask` 키**는 지원 앱에만(일반 답장은 null). 예전 앱에는 키를 넣지 않음.
